\section{Purpose and Architectural Principles}
This document synthesises the Elaboration-phase Software Architecture Document (\texttt{docs/analysis-and-design/architecture.md}),
detailed class and sequence models (\texttt{class-model.md}, \texttt{sequence-diagrams/}), Architecture Decision Records (ADRs
0001--0015), and Construction Test Plan v2.0 (\texttt{docs/test/test-plan.md}) for OmniCourse.

Three hard invariants govern every component:
\begin{enumerate}
  \item \textbf{Deterministic academic authority (Hard Rule 1, ADR 0013):} Every academic computation---GPA in integer tenths,
        chronological retake resolution, requirement coverage, single-hop overflow, combined minimums, prerequisites, offering
        terms and training-type credit caps (ADR 0012)---executes exclusively inside pure functions in
        \texttt{src/backend/src/rules/}, enforced at $\ge 80\%$ statement coverage in CI (100\% achieved at B1).
  \item \textbf{Link-only portal boundary (Hard Rule 2, ADR 0010):} OmniCourse never stores HCMUS portal passwords or
        automates registration; school tasks outside planning are served by versioned, SHA-256-checked guides.
  \item \textbf{Privacy by schema construction (Hard Rule 3, ADR 0003, ADR 0004):} Every user-owned table carries
        \texttt{user\_id uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE}, verified against \texttt{pg\_constraint} in e2e
        tests so account export and 30-day grace purge cover every table automatically without leaking credential columns.
\end{enumerate}

\section{C4 Container and Component View}
OmniCourse is deployed as a modular monolith behind Cloudflare and Nginx:
\begin{itemize}
  \item \textbf{Single-Page Application (\texttt{src/frontend}):} Vue 3.5.44, Vite 8.3.4, Pinia 4.1.0 and \texttt{vue-router}
        5.4.0, bilingual (Vietnamese and English) with light and dark themes and lazy per-route chunks.
  \item \textbf{REST API (\texttt{src/backend}):} NestJS 12.1.3 on Node 22.22.1 with TypeORM 1.1.2, global
        \texttt{ThrottlerGuard} and default-deny \texttt{AuthGuard}, publishing a drift-tested OpenAPI 3.2.0 contract
        (\texttt{src/backend/openapi.json}).
  \item \textbf{Database:} PostgreSQL 18.6 managed strictly through ordered TypeORM migrations (\texttt{synchronize: false}),
        with insert-only provenance-checked curriculum and guide seeds.
  \item \textbf{AI Gateway (\texttt{src/backend/src/ai}):} Scoped strictly to F6's goal box and F8's advisor chat (ADR 0003),
        guarded by advisory-locked daily per-user quotas and zero-content usage rows.
\end{itemize}

\section{Verification Strategy and B1 Baseline}
Test Plan v2.0 defines six verification tiers: co-located Vitest unit specs, PostgreSQL 18.6 e2e specs (including
\texttt{pg\_stat\_activity} row-lock contention and PL/pgSQL fault injection), Chromium browser tests, independent academic
fixture checks, throttled latency/accessibility runs, and sprint acceptance reports. Build \texttt{B1} achieved 100\%
rule-engine statement coverage and $< 1.05\text{ s}$ audit/dashboard load across 130 production runs (\texttt{report-b1.md}).
