# ADR 0005: Curriculum cohorting and course catalog

- Status: accepted (2026-11-27, Lâm)
- Date: 2026-11-03
- Deciders: Triết (owner of `curriculum` and `rules`), Lâm (Project Lead)
- Reviewer: Thắng (F12 curriculum administration and seeds), Hoà (F4 explorer and F5 planner)

## Context

The [glossary](../../../GLOSSARY.md) defines a *Curriculum* as the courses and requirement groups a cohort of a program must satisfy to graduate. Vision §5 (F3 degree audit, F4 curriculum explorer, F5 planner, F12 curriculum administration), Vision §6 Data ("curriculum data versioned per cohort, so a new cohort is a new record and old plans keep working"), and SDP §4.2 all require per-cohort curriculum versions ([ADR 0001](0001-technology-stack.md)).

An initial draft schema treated `curriculums.code` as globally unique without a parent `programs` table and attached courses directly to a single requirement group. That shape prevented sharing general-education and foundation courses across cohorts or programs, made it impossible for one course code to appear in multiple cohorts or requirement groups, and carried a duplicate link-level `compulsory` boolean alongside the group's own kind.

## Decisions

| Decision | Alternatives rejected | Evidence |
| --- | --- | --- |
| **Introduce `programs`, and scope `curriculums` by `(program_id, cohort_year)`.** A `program` holds `code` (unique), `name_vi`, `name_en`, `faculty`, and `training_type` ([ADR 0012](0012-credit-caps-by-training-type.md), [ADR 0013](0013-rule-engine-and-degree-audit.md)). Each `curriculum` references `programs(id) ON DELETE RESTRICT` with `UNIQUE (program_id, cohort_year)` (`uq_curriculums_program_cohort`). Each of the nine CLC 2025 specializations is modelled as its own `program` so "one curriculum per program and cohort" holds uniformly. | A flat `curriculums` table with no `programs` parent; mutating one curriculum across cohorts; a separate specialization hierarchy in v1 | Vision §6 Data ("curriculum data versioned per cohort"); GLOSSARY (*Program*, *Cohort*, *Curriculum*); migration `1792912952302-create-curriculum-course-schema.ts` and `curriculum-seeds.spec.ts`. |
| **Make `courses` a shared catalog keyed by `code`, linked per cohort via `requirement_group_courses`.** `courses` stores `code` (`^[A-Z0-9]{2,20}$`, matching [ADR 0007](0007-transcript.md)), `name_vi`, `name_en`, `credits`, and teaching periods (`theory_periods`, `lab_periods`, `exercise_periods`, `project_periods`), owned by no requirement group. `requirement_group_courses` joins `(requirement_group_id, course_code)` with `ON DELETE CASCADE` from `requirement_groups` and `ON DELETE RESTRICT` from `courses`. | Courses owned by one `requirement_group_id`; `ON DELETE CASCADE` from `courses` | Shared courses appear across cohorts and across APCS and CLC 2025 without duplicating catalog rows. `ON DELETE RESTRICT` prevents deleting a catalog course still linked by any curriculum (`curriculum.e2e-spec.ts`, [ADR 0011](0011-curriculum-administration.md)). |
| **Keep compulsory vs. elective only on `requirement_groups.kind`.** `requirement_groups.kind` is `compulsory` (with fixed `credits_total`) or `elective` (with `credits_total_min`); `requirement_group_courses` carries no `compulsory` flag. A printed group that mixes BB and TC rows is seeded as two groups, `<name>: bắt buộc` and `<name>: tự chọn`, with the printed total preserved in `official_notes` (Project Lead decision, 2026-11-03). | A `compulsory` column on `requirement_group_courses`; keeping mixed BB/TC groups unsplit | One source of truth on the group prevents conflicting group/link flags in the rule engine ([ADR 0013](0013-rule-engine-and-degree-audit.md)). `curriculum-seeds.spec.ts` checks every split group (such as APCS `Kiến thức Computer Science (A)` = 40 + 16 = 56) against independently typed printed totals. |
| **Resolve cross-cohort catalog differences through explicit human decisions.** When the APCS 2024 and 2025 PDFs print different values for the same course code, the shared catalog keeps one value per code—taking the newer curriculum's value because the school names the course that way today—and records each approved difference in `seeds/apcs-catalog-decisions.ts`. Any unrecorded conflict throws `CatalogConflictError`. | Letting the last-seeded cohort silently overwrite earlier values; duplicating `courses` per cohort | Silent last-write-wins masks transcription typos and unreviewed cohort changes. `curriculum-seeds.spec.ts` asserts that every entry in `apcs-catalog-decisions.ts` matches both seeds and that removing any entry fails `buildCatalog`. |
| **Transcribe curriculum seeds into reviewed TypeScript structures with page-level provenance.** Seed TypeScript structures in `src/backend/src/curriculum/seeds/` were transcribed from the 16 scanned APCS PDF pages (`ChuongTrinhDaoTao_APCS_2024.pdf`, `ChuongTrinhDaoTao_APCS_2025.pdf`) and the CLC 2025 PDFs with model assistance and verified line-by-line by human review and `curriculum-seeds.spec.ts` provenance checks. | Runtime PDF extraction by a model (forbidden by [ADR 0003](0003-language-model-scope.md)); unreviewed SQL dumps without page provenance | [ADR 0003](0003-language-model-scope.md) permits dev-time model assistance when committed as human-reviewed code. `curriculum-seeds.spec.ts` checks page bounds, Unicode NFC text, ASCII `-` normalization, group credit sums, split subtotals and appendix matches independently of the seed loader. |

## Seed data

- 2026-11-26 (reconciled with [ADR 0003](0003-language-model-scope.md) on 2026-11-27): The APCS seed TypeScript structures were transcribed from the 16 scanned pages ("Trang n/16") of `ChuongTrinhDaoTao_APCS_2024.pdf` and `ChuongTrinhDaoTao_APCS_2025.pdf` with model assistance and verified line-by-line by human review against each printed page and by `curriculum-seeds.spec.ts` provenance checks. Names keep the PDF diacritics, and a dash is an ASCII `-`, because the PDF mixes `-` and `–` for one course.
- 2026-11-26: The CLC 2025 seeds ("Chương trình tăng cường tiếng Anh" of ngành Công nghệ thông tin, 7480201) come from one booklet, `TCTA_CTDT_2025_Khoa-2025-all.pdf` ("Trang n/73"), for the structure, the totals and the group pages, and from one table PDF per specialization for the rows. A program has one curriculum per cohort, so each of the nine specializations is its own program.
- 2026-11-26: A CLC 2025 table PDF (`TCTA_CTDT_2025_<KEY>.pdf`) prints no page numbers, so the page of a row is the physical page of that file. The group of a row follows the "Nhóm kiến thức" column of the table, checked against sections 7.1 to 7.2.3 of the booklet. In each group, the course codes of a specialisation file keep the printed row order (STT); each course's name, credits and periods are written once in `clc-2025-courses.ts`. The groups follow the order of the `ClcRows` keys, so in `clc-2025-cnttin.groups.ts` the first eight free-elective rows (STT 91–98) come after the graduation rows (STT 99–127).
- 2026-11-26: A seed row lists the columns in the order of the printed table: `code`, Tên HP (`name_vi`), Số TC (`credits`), LT (lý thuyết, `theory_periods`), TH (thực hành, `lab_periods`), BT (bài tập, `exercise_periods`), ĐT (thực hiện đề tài, `project_periods`) and `page`. A blank cell is `null`. A column that the table does not print is `0`.
- 2026-11-26: A seed file mirrors the printed tables row by row, so a reviewer can hold the page next to the file. `curriculum/seed-curricula.ts` writes the stored columns; the others (`page`, subtotals, discrepancies, `needs_check`) stay as review metadata.
- 2026-11-26: `curriculum/seeds/curriculum-seeds.spec.ts` types its expected values, such as the printed groups that mix BB and TC rows and their totals, from the PDFs. It does not read them from the seed, so one change to the data cannot move both sides at once.

## Consequences

- Multiple cohorts and programs coexist without duplicating course catalog entries.
- Plans and transcripts reference canonical course codes stably while requirement membership is explicit per curriculum and requirement group.
- Deleting a requirement group cascades its `requirement_group_courses` links while preserving catalog `courses`, and `ON DELETE RESTRICT` prevents removing referenced catalog courses, programs or rule-linked groups.
