#### What the times show (for Hoà and Triết)

An edit sends the save and then the check, one after the other (`PUT …/placements`, then `GET …/issues`). Their server times alone add up to 255–275 ms at the median, which leaves 25–45 ms for the browser before the 300 ms limit. Nearly every run that stayed under 300 ms did so by that margin. The rule-engine work is not the only part: a `PUT` of the board alone takes about 140 ms. So the limit is missed by the two requests in sequence, not by rendering. Per the procedure, each run of 300 ms or more stays in the report even if a later rerun passes.
